# E学慧通第一期学生端 Demo 设计系统

> 设计依据：严格参考 `学生端 Demo.html`。本设计系统用于约束 PRD 和交互原型，不再采用路线图中的阶段化产品假设。

## 1. 设计定位

- 产品形态：学生/家长端微信小程序。
- 评审形态：左侧演示控制台 + 右侧手机预览。
- 核心页面：首页、课程、作业、我的、学情档案。
- 核心状态：已绑定学生、已登录未绑定、游客。
- 核心气质：干净、轻快、学习服务导向，突出作业和学情闭环。

## 2. 布局规范

| 区域 | 规范 |
| --- | --- |
| 外层页面 | 桌面评审时使用左右布局，左侧为控制面板，右侧为手机预览 |
| 左侧控制面板 | 包含演示端、访问状态、快速查看、运营弹窗 |
| 手机外壳 | 模拟微信小程序手机界面，顶部状态栏 + 页面标题 + 微信胶囊按钮 |
| 页面内容区 | 卡片式信息流，底部固定四栏导航 |
| 底部导航 | 首页、课程、作业、我的，4 个等宽按钮 |

## 3. 色彩规范

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--blue` | `#1677FF` | 主操作、提交作业、选中态 |
| `--cyan` | `#12B7C8` | 课程卡片、直播课高亮 |
| `--orange` | `#FF8A1F` | 学情档案、待处理、提醒 |
| `--green` | `#23C16B` | 已完成、良好状态 |
| `--red` | `#F05252` | 推荐课、风险或强调 |
| `--text` | `#1F2A44` | 主文字 |
| `--muted` | `#8D96A6` | 辅助文字 |
| `--bg` | `#F4F8FF` | 小程序页面背景 |
| `--card` | `#FFFFFF` | 卡片背景 |
| `--line` | `#E6ECF5` | 分割线和边框 |

## 4. 字体与信息层级

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 17-18px | 700 | 顶部 `miniTitle` |
| 模块标题 | 16-18px | 700 | 作业任务、公益课程、学情档案 |
| 卡片标题 | 14-16px | 700 | 课程名、作业名 |
| 正文 | 13-14px | 400/500 | 时间、说明、状态 |
| 辅助文字 | 12px | 400 | 截止时间、同步说明 |

## 5. 组件规范

| 组件 | 规范 |
| --- | --- |
| 访问状态分段控件 | 三个按钮：已绑定学生、已登录未绑定、游客；选中态蓝底白字 |
| 快速查看按钮 | 首页、课程、作业、我的；与底部导航状态同步 |
| 身份卡 | 头像 + 姓名 + 年级班级标签 + 学习账号 |
| Notice 提醒条 | 浅色背景，左侧说明，右侧小按钮 |
| 快捷卡 | 两列网格，蓝色提交作业、橙色学情档案 |
| 作业卡片 | 左侧学科图形，右侧标题、时间、状态和操作 |
| 课程卡片 | 标题、说明、操作按钮；支持默认、青色、红色变体 |
| Tab | 胶囊按钮，横向排列，当前项蓝底白字 |
| 上传组件 | 三列网格：已上传页 + 添加按钮 |
| 指标卡 | 三列指标，展示正确率、提交次数、学习时长等 |
| 进度条 | 学科表现和课程观看进度 |
| Modal | 居中弹窗，包含标题、说明、操作按钮 |
| Toast | 底部轻提示，说明登录绑定限制或提交结果 |

## 6. 状态规范

| 状态 | 页面表现 |
| --- | --- |
| 已绑定学生 | 展示完整首页、作业列表、学情摘要和报告 |
| 已登录未绑定 | 展示手机号和绑定学生引导；作业和我的页显示绑定卡片 |
| 游客 | 首页展示“登录后可预约课程”；受限动作通过 Toast 提示 |
| 待提交 | 橙色状态标签，可进入提交 |
| 批改中 | 蓝色状态标签，展示已交 |
| 已批改 | 绿色状态标签，可查看报告 |

## 7. 交互规范

- 底部导航和左侧快速查看必须联动当前页面。
- 页面标题 `miniTitle` 随当前页面变化。
- “提交作业”快捷入口进入作业页的提交作业视图。
- “学情档案”和“报告”进入报告页。
- “立即预约”触发公益课预约弹窗。
- “触发公益课弹窗”打开公益课推荐弹窗。
- 未绑定访问作业时展示绑定拦截。
- 游客访问受限功能时展示 Toast。

## 8. 原型一致性检查

- 文案应直接沿用 Demo，如“今日有 2项作业 待完成”“绑定后可查看作业”。
- 页面结构应保持 Demo 的五个页面：home、course、homework、profile、report。
- 不在原型中加入“二期预留”“商城跳转”“支付”等 Demo 外表达。
- 学情档案必须包含作业正确率、提交次数、课程学习和学科进度。
- 课程观看模块必须保留“小鹅通同步”和“数据可能存在数分钟延迟”的说明。

## 9. 后台端设计定位

- 产品形态：内部运营/教务/技术支持使用的管理后台。
- 设计目标：高效、清晰、可追踪；重点是配置、校验、同步、排错。
- 风格：SaaS 管理台，不做营销式大图和宣传页。
- 主色：沿用学生端蓝色 `#1677FF`，后台补充深色侧边栏 `#1E293B` 和橙色风险/操作强调 `#F97316`。

## 10. 后台端页面结构

| 页面 | 核心内容 |
| --- | --- |
| 总览 | 账号数、绑定率、课程配置数、作业提交、同步失败 |
| 账号导入 | 模板下载、文件上传、字段校验、导入预览、错误明细 |
| 学生绑定 | 按手机号/学生/学习账号检索，手动绑定，冲突处理，绑定日志 |
| 课程配置 | 第三方课程源、课程映射、学生端展示配置、公益课弹窗配置 |
| 作业接口 | 第三方作业服务配置、作业任务映射、提交转发、批改回调 |
| 数据落库 | 学生、课程、作业、提交、批改、学情报告的数据入库状态 |
| 同步日志 | 第三方请求、响应、回调、失败原因、重试 |

## 11. 后台端组件规范

| 组件 | 规范 |
| --- | --- |
| 侧边栏导航 | 固定左侧，模块名称清晰，当前页面蓝色高亮 |
| 顶部工具条 | 页面标题、环境标签、角色、主要操作按钮 |
| 指标卡 | 4-6 个核心指标，紧凑展示，不使用大面积装饰 |
| 数据表格 | 支持状态标签、操作列、更新时间，默认按异常/最近更新排序 |
| 上传面板 | 展示模板、拖拽/选择文件、校验结果、确认导入 |
| 配置表单 | 分组展示服务商、API、鉴权、同步频率、状态 |
| 状态标签 | 正常为绿色，警告为橙色，失败为红色，同步中为蓝色 |
| 日志抽屉/详情 | 展示 request_id、第三方 ID、请求摘要、响应摘要、错误原因 |

## 12. 后台端交互原则

- 所有破坏性或批量操作必须二次确认。
- 导入账号必须先校验预览，再确认入库。
- 第三方密钥不明文展示，只允许更新或重新生成。
- 小程序不直接对接第三方；后台配置后由我们后端统一转发。
- 数据以我们平台落库结果为准，第三方同步异常必须可检索、可重试。
- 异步操作需要 loading 或进度反馈，避免页面无响应。
