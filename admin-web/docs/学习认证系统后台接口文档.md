# E学慧通学习认证系统后台接口文档

## 1. 文档说明

本文档根据当前管理端页面已实现的业务逻辑编写，供若依后端、前端联调和测试使用。

- 前端技术栈：Vue 3、Element Plus、Vite。
- 后端建议：RuoYi-Vue Spring Boot。
- 接口风格：RESTful JSON API。
- 文件上传：`multipart/form-data`。
- 日期时间：`yyyy-MM-dd HH:mm:ss`。
- 时区：`Asia/Shanghai`。
- 鉴权方式：沿用若依 JWT，请求头携带 `Authorization: Bearer {token}`。
- 数据范围：学员、课程和资料均应按若依部门或业务组织的数据权限过滤。

当前前端为模拟数据版本。本文档定义的是正式接入后端时的目标接口契约。

## 2. 基础约定

### 2.1 接口前缀

```text
/study/student
/course/course
/course/material
/course/treasure
```

若项目网关统一添加 `/api`，则实际请求地址为：

```text
/api/study/student/list
```

### 2.2 通用请求头

| 请求头 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `Authorization` | 是 | `Bearer eyJ...` | 若依登录令牌 |
| `Content-Type` | 是 | `application/json` | JSON 请求 |
| `Content-Type` | 是 | `multipart/form-data` | 文件上传请求 |

### 2.3 普通响应结构

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | `200` 表示成功，其他值表示失败 |
| `msg` | String | 操作结果或错误提示 |
| `data` | Object / Array / null | 业务数据 |

### 2.4 分页响应结构

沿用若依表格分页结构：

```json
{
  "code": 200,
  "msg": "查询成功",
  "total": 126,
  "rows": []
}
```

### 2.5 分页请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `pageNum` | Integer | 否 | `1` | 当前页码 |
| `pageSize` | Integer | 否 | `10` | 每页条数 |
| `orderByColumn` | String | 否 | `updateTime` | 排序字段 |
| `isAsc` | String | 否 | `desc` | `asc` 或 `desc` |

### 2.6 枚举定义

#### 年级 `grade`

| 值 | 显示文本 |
| --- | --- |
| `SENIOR_ONE` | 高一 |
| `SENIOR_TWO` | 高二 |
| `SENIOR_THREE` | 高三 |

#### 学科 `subject`

| 值 | 显示文本 |
| --- | --- |
| `MATH_ELITE` | 数学培优 |
| `MATH_ADVANCE` | 数学跃升 |
| `PHYSICS` | 物理 |
| `ENGLISH` | 英语 |
| `CHINESE` | 语文 |

#### 资料类型 `materialType`

| 值 | 显示文本 |
| --- | --- |
| `HANDOUT` | 讲义 |
| `HOMEWORK` | 作业 |

#### 资料开放状态 `openStatus`

| 值 | 显示文本 | 判断逻辑 |
| --- | --- | --- |
| `SCHEDULED` | 待开放 | 当前时间早于开放时间 |
| `OPEN` | 已开放 | 当前时间大于等于开放时间 |

建议开放状态由后端根据 `openTime` 动态计算，不单独维护可修改字段。

#### 课程状态 `status`

| 值 | 显示文本 |
| --- | --- |
| `ENABLED` | 已启用 |
| `DISABLED` | 已停用 |

#### 手机号授权状态 `phoneStatus`

| 值 | 说明 |
| --- | --- |
| `BOUND` | 已填写授权手机号 |
| `UNBOUND` | 未填写授权手机号 |

#### 文件处理状态

| 值 | 说明 |
| --- | --- |
| `PARSING` | 正在解析 |
| `SUCCESS` | 解析成功 |
| `FAILED` | 解析失败 |
| `EXPIRED` | 临时文件或确认令牌已过期 |

## 4. 学员信息管理

### 4.1 学员对象

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `studentId` | Long | 更新时必填 | 学员主键 |
| `school` | String | 是 | 学校全称，最长 100 字符 |
| `grade` | String | 是 | 年级枚举 |
| `gradeName` | String | 返回 | 年级显示文本 |
| `className` | String | 是 | 班级，最长 50 字符 |
| `studentName` | String | 是 | 学员姓名，最长 50 字符 |
| `studentNo` | String | 是 | 学号，同一业务组织内唯一 |
| `courseIds` | Long[] | 是 | 授权课程 ID，至少一项 |
| `courses` | Object[] | 返回 | 已授权课程摘要 |
| `authorizedPhone` | String | 否 | 授权手机号，11 位中国大陆手机号 |
| `phoneMasked` | String | 返回 | 脱敏手机号，例如 `138****6021` |
| `phoneStatus` | String | 返回 | `BOUND` 或 `UNBOUND` |
| `phoneSource` | String | 返回 | 手机号来源：后台录入、Excel 导入、H5 验证绑定 |
| `phoneVerifiedAt` | String | 返回 | H5 验证码校验成功时间 |
| `createTime` | String | 返回 | 创建时间 |
| `updateTime` | String | 返回 | 更新时间 |

### 4.4 新增学员

```http
POST /study/student
Content-Type: application/json
```

权限标识：

```text
study:student:add
```

请求示例：

```json
{
  "school": "北京市海淀实验中学",
  "grade": "SENIOR_ONE",
  "className": "3班",
  "studentName": "张晨",
  "studentNo": "2026010318",
  "courseIds": [1001, 1002],
  "authorizedPhone": "13812346021"
}
```

校验规则：

1. 学校、年级、班级、姓名、学号、授权课程必填。
2. 授权课程至少选择一门，且课程必须存在并处于启用状态。
3. 手机号非必填；填写时必须符合 `^1\d{10}$`。
4. 学号在同一数据权限范围内不可重复。
5. 授权手机号是否允许对应多个学员，由后端业务规则决定；若不允许，应返回明确冲突提示。

响应示例：

```json
{
  "code": 200,
  "msg": "学员新增成功",
  "data": {
    "studentId": 9001
  }
}
```

### 4.5 修改学员

```http
PUT /study/student
Content-Type: application/json
```

权限标识：

```text
study:student:edit
```

请求示例：

```json
{
  "studentId": 9001,
  "school": "北京市海淀实验中学",
  "grade": "SENIOR_ONE",
  "className": "3班",
  "studentName": "张晨",
  "studentNo": "2026010318",
  "courseIds": [1001, 1002],
  "authorizedPhone": "13812346021"
}
```

处理要求：

- `courseIds` 以本次提交为准，全量覆盖原授权课程。
- `authorizedPhone` 传空字符串或 `null` 表示取消手机号授权。
- 修改学校、年级、班级和学号时，应保留操作日志。

### 4.7 校验 Excel 导入文件

此接口只解析和校验，不写入正式学员表。

```http
POST /study/student/import/validate
Content-Type: multipart/form-data
```

```text
study:student:import
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | File | 是 | `.xlsx` 或 `.xls` |

限制建议：

- 单次最多 2,000 条。
- 文件最大 10 MB。
- 临时文件和 `importToken` 有效期建议为 30 分钟。

### 5.4 上传讲师头像

课程保存前先上传讲师头像，取得正式访问地址后再提交新增或修改课程接口。

```http
POST /course/course/lecturer-avatar
Content-Type: multipart/form-data
```

权限标识：

```text
course:course:add
```

编辑课程时也允许拥有 `course:course:edit` 权限的用户调用。

表单参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | File | 是 | 讲师头像 |

校验规则：

1. 仅支持 JPG、JPEG、PNG 和 WebP。
2. 文件大小不得超过 2MB。
3. 后端必须根据文件内容校验真实 MIME 类型，不能只信任文件扩展名。
4. 建议将头像裁切或压缩为正方形 WebP，并使用随机文件名存储。

响应示例：

```json
{
  "code": 200,
  "msg": "讲师头像上传成功",
  "data": {
    "lecturerAvatarUrl": "https://static.example.com/lecturer/20260625/a8f32e.webp",
    "width": 400,
    "height": 400
  }
}
```

### 5.5 新增课程

```http
POST /course/course
Content-Type: application/json
```

权限标识：

```text
course:course:add
```

请求示例：

```json
{
  "grade": "SENIOR_ONE",
  "subject": "PHYSICS",
  "lecturerName": "王天宇",
  "lecturerAvatarUrl": "https://static.example.com/lecturer/20260625/a8f32e.webp",
  "sourceValue": "https://app.xiaoe-tech.com/detail?id=physics-a1",
```

2. `lecturerName` 去除首尾空格后长度为 1-30 个字符。
3. `lecturerAvatarUrl` 非必填；填写时必须是本系统头像上传接口返回的有效地址。
4. `classTimes` 必填，至少包含一组上课时间，允许一次创建多个课次。
5. 每组上课时间必须同时包含 `startTime` 和 `endTime`。
6. `endTime` 必须晚于 `startTime`。
7. 同一课程的多个上课时间段不得重叠，完全重复的时间段不得保存。
8. 建议同一讲师或同一直播资源的跨课程冲突由后端根据实际排课规则进一步校验。
9. 后端负责从链接中解析第三方课程 ID。
10. 后端调用小鹅通服务校验课程是否存在、是否可访问。
11. 同一年级与学科是否允许重复课程，建议配置为不允许。
12. 新增课程默认状态为 `ENABLED`。
13. 课程主表和全部上课时间必须在同一事务内创建。

```json
  "msg": "课程创建成功",
  "data": {
    "courseId": 1002,
    "externalCourseId": "physics-a1",
    "scheduleIds": [20001, 20002]
  }
}
```

### 7.5 确认创建提分宝上传记录

```text
UNIQUE(homework_material_id, deleted)
```

## 8. H5 学生端展示与提交接口

### 8.1 时间判断原则

H5 中所有时间相关状态必须以服务端时间为最终依据。

1. 接口统一返回 `serverTime`，格式为 `yyyy-MM-dd HH:mm:ss`，时区为 `Asia/Shanghai`。
2. 前端可使用本地时间做分钟级界面刷新，但不得仅依赖手机本地时间决定资料开放或作业是否可提交。
3. 资料查询、作业详情和作业提交接口均必须在服务端重新判断当前时间。
4. 时间临界点统一采用以下规则：
   - 上课时间：仅选择 `startTime > serverTime` 的下一条课次。
   - 资料展示：`serverTime >= displayTime` 时显示。
   - 作业提交：`serverTime <= submitDeadline` 时允许提交。
   - 当 `serverTime > submitDeadline` 时提交关闭。

### 8.2 查询 H5 学生主页

```http
GET /h5/student/home
```

鉴权要求：

- 学生登录态必填。
- 后端根据当前学生的课程授权关系返回数据。

响应示例：

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "serverTime": "2026-06-25 16:20:00",
    "student": {
      "studentId": 9001,
      "studentName": "慧小聚",
      "gradeName": "高三",
      "phoneMasked": "176****0909"
    },
    "courses": [
      {
        "courseId": 1002,
        "courseName": "高一物理",
        "subject": "PHYSICS",
        "subjectName": "物理",
        "externalCourseUrl": "https://app.xiaoe-tech.com/detail?id=physics-a1",
        "nextClassTime": {
          "scheduleId": 20001,
          "startTime": "2026-07-02 14:00:00",
          "endTime": "2026-07-02 16:00:00"
        },
        "materialCount": 1,
        "hasNewMaterial": true,
        "homeworkStatus": "PENDING",
        "treasureStatus": "NOT_GENERATED"
      }
    ]
  }
}
```

下一次上课时间计算规则：

1. 查询当前课程全部未删除的课次。
2. 过滤 `startTime > serverTime` 的课次。
3. 按 `startTime` 正序取第一条。
4. 如果没有未来课次，`nextClassTime` 返回 `null`，H5 显示“暂无未开始课次”。
5. 已经开始但尚未结束的课次不属于“下一次还未到的上课时间”，不作为 `nextClassTime` 返回。

### 8.3 发送手机号验证码

```http
POST /h5/auth/phone/code
Content-Type: application/json
```

请求示例：

```json
{
  "studentId": 9001,
  "phone": "13812346021",
  "scene": "STUDENT_PHONE_BIND"
}
```

响应示例：

```json
{
  "code": 200,
  "msg": "验证码已发送",
  "data": {
    "verificationToken": "phone-code-20260625-a17f90",
    "phoneMasked": "138****6021",
    "expiresIn": 300,
    "retryAfter": 60
  }
}
```

发送规则：

1. 当前 H5 登录态必须对应 `studentId`，不得替其他学员发送。
2. 手机号必须符合 `^1\d{10}$`。
3. 验证码建议 6 位数字，有效期 5 分钟。
4. 同一手机号 60 秒内不得重复发送。
5. 同一手机号、学生、IP 和设备均应配置小时及每日发送上限。
6. 响应和日志不得返回明文验证码。
7. `verificationToken` 只能用于当前学生、手机号和 `STUDENT_PHONE_BIND` 场景。

### 8.4 校验验证码并同步授权手机号

验证码校验与学员手机号写回必须由一个接口原子完成。

```http
POST /h5/student/phone/bind
Content-Type: application/json
```

请求示例：

```json
{
  "studentId": 9001,
  "phone": "13812346021",
  "verificationToken": "phone-code-20260625-a17f90",
  "verificationCode": "493821"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "手机号验证成功，已同步至学员信息",
  "data": {
    "studentId": 9001,
    "phoneMasked": "138****6021",
    "phoneStatus": "BOUND",
    "phoneSource": "H5_VERIFIED",
    "phoneSourceName": "H5 验证绑定",
    "phoneVerifiedAt": "2026-06-25 16:32:00",
    "synced": true
  }
}
```

处理规则：

1. 校验当前登录学员与 `studentId` 一致。
2. 校验 `verificationToken` 未过期、未使用且绑定当前手机号。
3. 验证码错误次数超过限制后令牌失效。
4. 验证成功后，在同一数据库事务内更新：
   - `authorizedPhone`
   - `phoneStatus=BOUND`
   - `phoneSource=H5_VERIFIED`
   - `phoneVerifiedAt`
   - `updateTime`
5. 同时写入手机号绑定审计记录，包含原手机号、新手机号、来源、操作时间和设备摘要。
6. 事务成功后才消费验证码令牌并返回 `synced=true`。
7. H5 只有收到 `synced=true` 后才进入“课程已成功开通”页面。
8. 管理端重新查询学员列表或详情后，应直接展示同步后的授权手机号和来源。

手机号冲突规则：

- 如果一个手机号允许绑定多个兄弟姐妹学员，应通过业务配置明确允许。
- 如果手机号要求唯一，已绑定其他学员时返回冲突，不得覆盖原数据。
- 学员重新验证同一手机号时按幂等成功处理。
- 学员更换手机号时必须完整执行新手机号验证码流程，不能只提交新号码。

冲突响应示例：

```json
{
  "code": 40906,
  "msg": "该手机号已绑定其他学员，请联系老师处理"
}
```

### 8.5 查询 H5 课程资料列表

```http
GET /h5/course/{courseId}/materials
```

响应示例：

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "serverTime": "2026-06-25 16:20:00",
    "courseId": 1002,

        "displayTime": "2026-06-20 08:00:00",
```

服务端过滤规则：

```text
未删除
AND 所属课程已授权给当前学生
```

补充要求：

- H5 响应中的 `displayTime` 对应管理端资料配置中的 `openTime`；后续建议统一字段名为 `displayTime`，避免“开放”和“显示”产生歧义。
- H5 列表接口原则上只返回已经达到显示时间的资料。
- `displayed` 字段可保留用于调试，但正常业务结果中始终为 `true`。
- 未到显示时间的资料不得通过详情接口或可猜测的文件地址提前下载。
- 静态文件下载地址建议使用带有效期的签名 URL。

## 12. 数据一致性与事务要求

1. 学员新增或修改时，学员主表和课程授权关系表必须在同一事务中提交。
2. Excel 导入应按批次记录导入日志，避免部分成功后无法追踪。
3. 课程删除、资料删除和提分宝删除均建议使用逻辑删除。
4. 文件从临时目录转入正式目录和数据库记录创建必须保持最终一致。
5. `importToken`、`uploadToken`、`parseToken` 必须一次性使用。
6. 所有批量、删除和高风险修改操作必须记录若依操作日志。
7. 小鹅通课程校验失败时不得创建或更新课程映射。
8. 完整手机号属于敏感字段，日志、列表和导出中默认脱敏。
9. H5 时间状态以服务端时间为准，作业提交接口必须在事务内重新校验截止时间。
10. 物理作业提交记录与提分宝生成任务必须在同一事务中创建，或通过可靠消息保证最终一致。
11. H5 手机验证码校验和学员授权手机号更新必须在同一事务中完成，不允许出现验证码成功但学员信息未同步的中间状态。

## 13. 前后端联调顺序

建议按以下顺序实施：

1. 年级、学科和课程下拉选项。
2. 课程列表、新增、修改和删除校验。
3. 学员列表、新增和修改。
4. 学员 Excel 模板、校验和确认导入。
5. 课程资料入口和资料列表。
6. 临时文件上传、批量新增资料和二次编辑。
7. 物理作业小题分及提交数据导出。
8. 提分宝 ZIP 解析、确认创建和批次删除。
9. H5 手机验证码发送、校验及授权手机号同步。
10. H5 下一次上课时间、资料按时间展示和物理作业截止状态。
11. H5 物理作业提交后进入提分宝生成中页面。
