# Admin Web 后端需求基线

## 1. 目标

为 `admin-web` 当前三个管理页面提供可落地的若依后端能力：

1. 学员信息管理。
2. 课程管理。
3. 课程资料与提分宝管理。

本规格只定义后端业务、数据、接口、安全和测试边界，不包含前端或后端代码实现。

## 2. 需求依据与优先级

发生冲突时按以下顺序判断：

1. `admin-web/src/views/**` 中已经呈现的页面行为。
2. `admin-web/docs/学习认证系统后台接口文档.md` 中的管理端接口。
3. `h5-project/src/pages/studentAuth/api/api.json` 与 `api/index.ts` 中已经使用的 `/auth/*` 契约。
4. 暑期提分宝 PRD 中与当前后台页面直接相关的业务规则。
5. 更大范围的 E学慧通一期 PRD 作为后续扩展背景，不自动纳入本期实现。

## 3. 本期范围

### 3.1 学员管理

- 分页查询、条件筛选和手机号脱敏。
- 新增、详情、修改。
- 学员与多门课程的授权关系。
- Excel 模板下载、文件校验、确认导入和查询结果导出。
- 后台录入、Excel 导入、H5 验证绑定三种手机号来源。
- 与既有 `/auth/*` 学生认证数据保持一致。

### 3.2 课程管理

- 年级、学科、状态筛选。
- 新增、详情、修改、启停和受控删除。
- 小鹅通链接或课程 ID 解析与有效性校验。
- 讲师姓名、头像和多课次时间维护。
- 授权学员数、资料数、提分宝批次数统计。

### 3.3 资料管理

- 按课程进入资料工作台。
- 讲义、作业多文件临时上传和批量确认。
- 每个文件独立设置开放时间。
- 物理作业配置题目数、各题满分和提交截止时间。
- 资料详情、修改、受控删除。
- 物理作业小题分数据导出。

### 3.4 提分宝管理

- 查询当前课程可关联的已开放作业。
- ZIP 临时上传、安全解压、学生文件匹配和错误清单。
- 确认创建批次，并保存每个学生对应的个人文件。
- 查询和删除批次。
- 为后续学生端鉴权下载预留个人文件与发布状态。

### 3.5 兼容范围

- 保留既有 `/auth/schools`、`/auth/grades`、`/auth/verify-student`、`/auth/bind-phone`、`/auth/bind-result`、`/auth/files/{fileId}/download` 的请求头和字段口径。
- 管理端与 `/auth/*` 必须共用学员、课程、授权关系和资料主数据，不得复制一套独立数据。

## 4. 非本期范围

- 完整小程序首页、作业中心、学情报告和课程观看数据。
- 新版 `/h5/*` 验证码、物理作业上传、答案解锁和提分宝状态接口的完整实现。
- 第三方 AI 批改、学科网自动接口、短信服务和消息通知。
- 后台四大一级模块的整体重构。
- 前端 API 接入和页面改造。

## 5. 核心业务规则

### 5.1 学员

1. 学号在同一业务组织内唯一。
2. 一个学员至少授权一门启用课程。
3. 本期手机号按“一个手机号只能绑定一个有效学员”实现，以兼容现有 `/auth/bind-phone` 的占用检查；未来如需兄弟姐妹共用手机号，应通过配置和数据迁移放开。
4. 列表、普通日志和默认导出不得返回完整手机号。
5. 修改授权课程时全量覆盖关系，但必须保留审计记录。
6. 多课程学员必须存在唯一主课程，以兼容旧 `/auth/*` 的单课程响应。

### 5.2 课程

1. 同一业务组织内，年级与学科组合默认唯一。
2. 新增课程默认启用。
3. 每门课程至少一个课次；结束时间必须晚于开始时间；同一课程课次不得重叠。
4. 小鹅通课程校验失败时不得写入或更新课程。
5. 存在学员授权、资料或提分宝时禁止物理删除；停用不删除历史关系。

### 5.3 资料

1. 开放状态由服务端根据 `openTime` 动态计算。
2. 临时上传令牌一次性使用并有过期时间。
3. 物理作业必须配置提交截止时间和连续的小题结构。
4. 每题满分允许 `1-20`，题目数允许 `1-30`；学生实际得分模型需支持 `0` 和小数，不能使用只允许正整数的字段设计。
5. 已有学生提交后，禁止修改题目数量和满分结构。
6. 作业已有提交记录时禁止删除。

### 5.4 提分宝

1. 一个作业只能有一个未删除的有效提分宝批次。
2. ZIP 中每个有效文件必须匹配当前课程授权学员。
3. 后端必须保存“批次”和“学生个人文件”两层数据，不能只保存 ZIP。
4. 当前页面没有独立发布按钮，因此本期“确认创建批次”同时视为发布；内部仍保留发布状态，便于后续增加审核发布。
5. 删除批次采用逻辑删除，并使作业恢复为可重新上传状态。
6. 任何学生只能下载属于自己的个人文件，不能直接访问 ZIP 或其他学生文件。

## 6. 用户故事与验收标准

### R1 学员查询

作为教务，我需要按关键词、年级、课程和手机号状态查询学员，以便维护报名和授权数据。

- 当管理员查询学员列表时，系统应按其数据权限过滤记录。
- 当列表返回已绑定手机号时，系统应只返回脱敏手机号和来源。
- 当关键词包含完整手机号时，系统可在后端匹配，但不得在响应中返回明文。

### R2 学员维护

作为教务，我需要新增或修改学员及其课程授权。

- 当保存学员时，系统应在同一事务中保存学员和课程关系。
- 当课程不存在或已停用时，系统应拒绝新增授权。
- 当手机号或学号冲突时，系统应返回明确业务错误。
- 当多门课程被授权时，系统应保证恰好一门主课程。

### R3 Excel 导入

作为教务，我需要先校验 Excel，再确认导入，避免错误数据直接入库。

- 当上传 Excel 时，系统应只生成临时校验结果，不写正式表。
- 当文件存在错误时，系统应返回行号、字段、原值和错误原因。
- 当确认导入时，系统应校验令牌未过期且未使用。
- 当重复确认同一令牌时，系统应拒绝重复写入。

### R4 课程维护

作为运营，我需要维护课程、讲师和课次。

- 当提交课程链接或 ID 时，系统应解析并通过小鹅通适配器校验。
- 当课次缺失、倒置或重叠时，系统应拒绝保存。
- 当删除被引用课程时，系统应返回各类关联数量。
- 当课程被停用时，系统应保留历史授权和资料。

### R5 资料上传

作为运营，我需要批量上传资料并分别设置开放时间。

- 当文件上传成功时，系统应返回一次性临时令牌。
- 当确认新增资料时，系统应原子创建全部有效记录；任一记录校验失败时不得部分提交。
- 当学生在开放时间前访问资料时，系统应拒绝返回文件内容或长期公开地址。

### R6 物理作业

作为物理教务，我需要配置小题满分和截止时间并导出学生得分。

- 当保存物理作业时，系统应校验题号连续、数量一致和截止时间有效。
- 当已有提交记录时，系统应拒绝修改小题结构。
- 当导出小题分时，系统应按题目动态生成列，并包含未提交学生。

### R7 提分宝

作为教务，我需要上传学科网返回的 ZIP，并让系统匹配到学生。

- 当解析 ZIP 时，系统应防止路径穿越、ZIP 炸弹和非法文件类型。
- 当文件无法匹配当前课程学员时，系统应返回错误清单并禁止确认。
- 当确认成功时，系统应在同一事务中创建批次、个人文件记录和发布状态。
- 当学生下载时，系统应校验认证令牌、学生身份、文件归属和发布状态。

### R8 旧 H5 兼容

作为现有 H5 用户，我需要后台切换为正式数据后仍能完成认证、绑定和资料下载。

- 当旧 H5 使用请求头 `token` 访问认证接口时，系统应继续接受该协议。
- 当旧 H5 查询单课程结果时，系统应返回学员主课程，不随机选择。
- 当后台修改学员手机号、课程授权或资料时，旧 H5 后续查询应读取同一份最新主数据。

## 7. 完成定义

- 数据库迁移脚本、权限菜单脚本和字典脚本齐全。
- 管理端接口与既有文档路径一致，差异有迁移说明。
- `/auth/*` 契约回归测试通过。
- 核心事务、并发唯一性、文件安全和数据权限测试通过。
- OpenAPI 或同等接口文档可供前端联调。
